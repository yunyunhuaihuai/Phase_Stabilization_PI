# PI 控制与证据边界

用于 PI 的相位鉴别器电压是环内反馈。Red Pitaya 读取该电压并通过串口调整 ODL；86100C 独立观察输出端信号，当前实验由本人在仪器上手动查看测量结果，读数不进入 PI 或控制量计算。具体测量项、参考方式和测量窗口须按实际仪器设置记录，当前未提供这些设置或实测指标。

控制对象是相位鉴别器电压与延迟线命令坐标之间的闭环。工作点建立先检查驱动归零、归中与停止/目标一致性，再寻找电压过零附近的局部单调区，最后用四个同向驱动报告坐标拟合局部斜率。测得的符号用于控制极性；增益只作为启动检查与日志证据，PI 系数不自动重整定。

控制链路为 `ReadPhase → DiscretePI::Compute → EvaluateCommandProposal → SendPosCmd`，仅在 `full` 模式下调用 `LogCycle`。所有相位读取必须有限。极性修正发生在 PI 内部；防飞车采用原始目标电压与采样电压之差的绝对值。逻辑目标保持浮点状态，物理命令是整数绝对坐标。

`BumplessTransfer` 设置积分为当前命令坐标，而没有减去当时比例项，因此首拍可能产生比例动作。死区冻结既保持输出又保持积分。步数和位置饱和使用反算，使积分与本次受限逻辑目标一致；发送失败后不做继续运行的状态回滚，而是停机。

串口每条完整命令有写入预算；截止时间后全部字节写入仍会被标为晚完成，并可能使位置发送失败。任何非空短写都会污染 ASCII 流，后续操作被隔离。没有请求编号，主动查询之后收到的状态帧也不能严格归因到该请求。帧解析目前检查结构，不验证 BCC。这些限制保留在日志元数据中。

四层证据必须分开：

| 层 | 本项目能记录的内容 | 不能据此证明的内容 |
|---|---|---|
| PI 提案 | 连续逻辑目标、整数物理目标 | 已发送、驱动执行 |
| 软件接受 | 本机串口完整接收字节或保持命令 | 到位、驱动已解析 |
| 驱动内部 | 速度、坐标、标志、报告年龄 | 独立机械位置、链路时延 |
| 独立仪器 | 当前为 86100C 手动观测；可选工具另记时延读数及查询包络 | 未记录的测量项、参考方式和窗口；未核验的采集时间与数据新鲜度 |

环内锁定标记只表示电压在死区内。它不能证明环外相位稳定，更不能证明延迟线机械到位。仿真接口返回的驱动报告也属于模拟状态，不是仪器证据。

`--log-mode full` 为默认值，维持既有文件格式及 Python runner 兼容性。`--log-mode off` 在主程序边界跳过所有日志打开、记录、健康检查和显式关闭调用，不创建周期 CSV、diagnostics、安全事件 CSV 或 metadata，也不启动周期写入线程。ADC、工作点建立、极性标定、PI 与积分反算、命令限幅、串口发送和故障处理仍执行；关键状态、错误及停止报告保留在终端。配置键集合、20 Hz 周期和名义 0.05 s 积分时间不变。`DataLogger` 的内部实现不变。

在 `full` 模式下，日志线程使用固定容量单生产者/单消费者队列。周期调用只复制记录；队列满或后台写入失败使 `Healthy()` 变为假。主循环检测后请求停止。退出刷盘、文件关闭失败会使进程失败。同步安全日志、调度延迟、串口和控制台操作影响时序，必须查看实测的软件时间字段，不能把 20 Hz 配置写成实时性指标。

仓库中的 `docs/simulation.png` 是离线仿真示例；README 提供五秒绘图复现命令。仿真 runner 加入明确声明的正弦电压干扰，并可生成原始与诊断 CSV。输出与统计均标记 `simulation`。图仅展示运行链路，未用于推断仪器性能。原始仿真日志可在本地按同一命令生成，公开仓库只保留图和生成入口。

已知接口限制：C++ 配置允许缺省项及重复键后值；正式 Python 实验要求完整且无重复的模板。温度失败返回 0，缺少独立故障标志。硬件 API 部分初始化调用没有逐项检查返回值。串口结构校验与软件保护不构成硬件安全认证。硬件部署前需核实这些接口与具体系统的要求。

`Compute` 依赖调用层提供有效配置、采集量程内的有限电压和正的有限计算周期。主循环检查 ADC 有限性；控制器本身没有对非有限周期或极端中间运算溢出提供独立防御。

## PI 输出与限幅

PI 计算的是**绝对逻辑目标位置**。每拍先计算经标定极性修正的误差 `e = polarity × (target − voltage)`，再计算 `P = Kp × e`、积分候选 `I + Ki × e × 0.05`。从 `P + I_candidate` 减去上拍逻辑目标得到增量，用于每拍限幅；最终输出仍是绝对目标。

步数饱和时，积分反算为 `I = limited_logical_candidate − P`；位置边界触发时同样反算。`|e| < deadband` 时保持上拍目标并冻结积分。初始化把积分和逻辑位置设为当前命令坐标，并注入标定极性；没有用标定增益自动重新整定 PI。

逻辑目标转换为整数时向零截断。负方向的物理目标为 `trunc(logical) − BACKLASH_STEPS`，正方向为 `trunc(logical)`，然后检查位置边界。此偏移按方向应用，不能解读为每次换向追加一段运动。默认偏移为零。

- 控制器的有效逻辑步数上限为 `min(MAX_STEP_PER_CYCLE, MAX_PHYSICAL_DELTA − BACKLASH_STEPS)`。
- 转换后若恰好多出一个脉冲，量化修正把物理目标压回每拍上限，并同步重置逻辑位置和积分。
- 发送审核再次检查整数目标的总行程与相对**上次软件接受目标**的物理步数。更大的越界提案被拒绝并停机。

控制器内部记录的是提出的目标。发送失败或审核拒绝后，主程序立即走故障停机路径，不继续使用已经前移的 PI 内部状态控制。

## 启动与保护

启动顺序为驱动配置、日志创建（仅 `full`）、归零、归中、盲扫、锚点两侧斜率检查、四点同向标定、最终有限采样检查和 PI 初始化。归零使用有超时与清理顺序的 `HomeWithSafety`；运动完成判定使用驱动内部状态及目标一致性。锚点斜率须同号且幅值 ≥ `0.5 × BASE_B0`；四点标定须 `R² ≥ 0.93`。这些门槛没有在演示中绕过。

发送前的防飞车检查保留以下软件判据：连续五拍误差增大且同向饱和；同向提案累计位移超过 200000 脉冲；误差超过 150 mV 持续 50 拍。只有连续 21 个合格样本满足误差 ≤ 0.5 mV、提案步数 ≤ 200 且未饱和，才重置同向位移累计。保护阈值没有经过本项目的硬件安全认证。

非有限相位输入、越界、保护触发或发送失败都会使运行失败；`full` 模式的队列满与日志错误同样使运行失败。干净串口上请求有地址的停止命令并做限时状态查询；出现非空 ASCII 短写后，连接永久隔离，不追加换行、重试或停机字节。此时软件报告停止状态未知，需要操作者通过独立硬件措施处理。

## 配置

`config.txt` 是完整的 PI 示例。默认参数用于离线演示，不能直接当作任何具体设备已验证的设置。未知键、非法数值和非有限值使加载失败。C++ 加载使用默认值补齐缺省项；重复键采用后值。Python 正式实验入口要求完整、无重复的已知键集合。

| 键 | 默认值 | 用途 / 校验 |
|---|---:|---|
| `CONTROL_FREQ_HZ` | 20 | 仅接受 20；PI 使用名义 0.05 s |
| `KP` / `KI` | 40 / 3200 | 比例、积分系数；非负且有限 |
| `TARGET_VPHS_MV` | 0 | 环内目标，绝对值 ≤ 900 mV |
| `DEADBAND_MV` | 0.15 | 严格小于此值时冻结，范围 0–2 mV |
| `MAX_STEP_PER_CYCLE` | 5500 | 逻辑每拍上限，1–8000 脉冲 |
| `MAX_PHYSICAL_DELTA` | 5500 | 软件接受目标之间的物理上限，≤ 8000 |
| `BACKLASH_STEPS` | 0 | 负向目标偏移，须小于物理上限 |
| `POS_MIN_LIMIT` / `POS_MAX_LIMIT` | 0 / 2112000 | 软件行程范围；须在固定总行程内 |
| `POS_CENTER` | 1056000 | 启动归中坐标，须在有效范围内 |
| `BASE_B0` | 0.0025 | 启动斜率检查参考，范围 0.0005–0.004 mV/脉冲 |
| `SWEEP_TOLERANCE_MV` | 2 | 寻零候选窗，大于 0 且 ≤ 2 mV |
| `MICROSTEP_RATIO` | 1 | 坐标约定只接受 1，不发送微步细分设置 |
| `BAUD_RATE` | 115200 | 只接受此波特率 |
| `TOTAL_DURATION_MIN` | 4 | 常规闭环运行时间，1–1440 分钟 |
| `FLUSH_INTERVAL` | 200 | 后台周期日志刷盘间隔，1–100000 条 |

8000 是软件允许的配置上限，不代表机械安全速度或硬件许可。启动宏运动使用单独的运动超时和行程约束，不能把闭环每拍上限当作启动步长。

## 日志与测量语义

`full` 模式每次运行创建 `Data_*` 原始 CSV、`.diagnostics.csv`、`.safety.csv` 和 `.metadata.txt`。实时循环向 512 条容量的队列提交记录，独立线程写周期日志；队列满不会阻塞控制循环，而会触发故障。安全事件同步记录。退出时排空、刷盘并检查关闭错误。

原始表前六列为 `Elapsed_s,V_PHS_mV,Temp_C,Logical_Pos,Physical_Pos,State`，其中两个位置列是**控制器提案**。后续列明确给出软件最后接受目标、发送结果、驱动状态与写入字节证据。

- `Proposed_*`：控制器提出的目标，包括最终被禁止发送的目标。
- `Last_accepted_*` / `Accepted_*`：完整本机串口写入或保持命令后的软件接受值；不证明驱动执行。
- `Driver_reported_*`：驱动内部状态，带有可用性和周期年龄；不等于机械测量。
- `Requested_u_steps` / `Submitted_u_steps`：逻辑目标增量，分别对应提案与软件接受转换后的变化。
- `Raw_error_mV,Integrator_steps,Lower_u,Upper_u`：PI 状态与有效增量边界。
- `Position_write_*` / `Fault_stop_*`：本机接收字节数、查询与未知停止状态。
- `Monotonic_s,Sample_dt_s,Compute_us,Previous_cycle_total_us,Deadline_late`：软件时序诊断。

`Sample_dt_s` 是 ADC 读取结束之间的软件间隔；PI 积分仍使用名义 0.05 s。名义周期不证明硬实时。后台磁盘操作不计入控制线程周期，但故障停机与同步安全事件可能阻塞。突然断电可能损失尚未刷盘的周期记录。

## 硬件采样与可选仪器工具的限制

ADC 接口读取 Red Pitaya 通道 1 的最新缓冲区，以 1024 降采样和约 2441 点均值产生 mV；此操作不证明缓冲区刷新率或采集时刻。温度接口使用固定 10 °C/V 转换，需独立确认标定，其读取失败目前返回 0。

可选 Python 仪器流程假定 2 GHz 载波；1 ps 对应 0.72° 是数学换算，不是实测性能。刺激频率到环内等效电压的系数须由操作者提供，离线预览的 1 Hz/mV 只是示例。脚本不主动改变射频功率。以上工具假设不能代替当前手动使用 86100C 时实际记录的测量项、参考方式和窗口。
